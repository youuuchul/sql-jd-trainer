# SQL JD Trainer 포트폴리오 자료

포트폴리오 사이트가 이 서비스를 소개할 때 참고하는 문서다. 화면 문구, 사용자 흐름, 구현 내용을 코드 기준으로 정리했다. 수치는 2026-11-04 운영 배포 기준이고, 쿼리 리뷰(세트 1개, 문제 3개)는 2026-11-06 브랜치 feat/query-review 기준이다(운영 게시 전).

- 서비스: https://sql-jd-trainer.vercel.app (로그인 없이 공개)
- 저장소: https://github.com/youuuchul/sql-jd-trainer
- 형태: 개인 프로젝트, 웹 앱(PWA 설치 가능), 데스크톱·모바일

## 1. 한 줄 소개

데이터 분석가 라이브 쿼리 테스트를 실무형 데이터로 연습하는 SQL 트레이너. 브라우저에서 바로 실행하고, 결과를 비교해 즉시 채점하며, 틀린 이유를 짚어 준다.

## 2. 문제와 해결

### 사용자가 겪는 문제

- 라이브 쿼리 테스트는 지표 정의를 읽고, 낯선 테이블 구조를 파악하고, 정해진 시간 안에 맞는 결과를 내야 한다. 문법 퀴즈형 연습으로는 이 과정이 연습되지 않는다.
- 회사마다 쓰는 SQL 방언(PostgreSQL, BigQuery, MySQL)이 달라 날짜·형변환·NULL 처리에서 막힌다.
- 오답이 나와도 "틀렸다"만 알고, 팬아웃·정수 나눗셈·NULL 같은 원인을 스스로 찾아야 한다.
- AI가 쿼리를 써 줘도, 결과를 검증하지 못하면 데이터 검증에서 헤맨다. 그럴듯한 쿼리에서 결함을 찾아내는 연습이 없다.
- 기본 함수는 한동안 안 쓰면 잊는다. 매일 조금씩 되짚을 장치가 없다.
- 지원하는 공고가 요구하는 역량에 맞춰 무엇을 연습할지 고르기 어렵다.

### 서비스가 주는 해결

- 실무 마트를 본뜬 데이터셋(쇼핑몰, 공공자전거, 직무별 6종, KPI 대시보드)에서 지표 정의를 읽고 쿼리를 쓴다.
- 문제마다 세 방언을 골라 브라우저에서 바로 실행한다. 설치나 가입이 필요 없다.
- 정답 결과와 비교해 즉시 채점하고, 오답이면 원인 라벨(예: "조인 팬아웃 의심", "정수 나눗셈 의심")과 누락 행을 보여 준다.
- 정답을 맞히면 해설(결과·조회 기준·인사이트), 방언별 정답 쿼리, 자주 나오는 오답이 열린다.
- 오늘의 카드: 함수 이름이나 인자 하나를 빈칸으로 채우는 카드를 하루 n장 푼다. 자주 쓰는 함수 위주로 나오고 응용은 가끔 섞인다. 풀고 나면 그 함수의 문법과 방언별 차이를 바로 본다. 틀린 카드는 5분 뒤 다시, 맞힌 카드는 간격을 늘려 복습한다. 매일 알림으로 불러낸다.
- 공고 분석: 채용 공고를 붙여넣으면 요구 역량을 찾아 맞는 문제를 추천한다.
- 쿼리 리뷰(AI가 쓴 쿼리 검증): 그럴듯하지만 결함이 심긴 쿼리와 그 결과를 보고, 결함이 있는 줄을 골라 유형(팬아웃, 중복 집계, NULL, 정수 나눗셈, 기간 경계 등)을 붙인다. 체크리스트로 채점하고, 직접 검증 쿼리를 돌려 숫자를 확인할 수 있다.

## 3. 핵심 장면

포트폴리오 챕터 후보. 한 장면 = 한 화면이다.

1. **브라우저에서 바로 실행하고 채점:** 문제 화면에서 방언을 고르고 쿼리를 실행하면 결과 표와 정답/오답 배너가 바로 뜬다. 같은 문제를 PostgreSQL, BigQuery, MySQL로 바꿔 풀 수 있다.
2. **틀린 이유를 짚는 채점:** 오답 배너 안에 원인 라벨과 설명이 붙고, "기대 결과에는 있는데 내 결과에 없는 행"을 보여 준다.
3. **실무 지표 문제:** 오른쪽 스키마 패널에 데이터 규칙·함정·지표 정의(예: 매출, 주문 고객)와 테이블 샘플이 있어, 읽고 정의를 쿼리로 옮기는 연습이 된다.
4. **문제 형식 여섯 가지:** 쿼리 작성 외에 깨진 쿼리 고치기, 객관식, 출력 예측(입력 표와 쿼리를 보고 결과를 적음), 결과 이상 찾기(잘못된 쿼리 결과에서 틀린 행을 고름), 쿼리 리뷰(결함이 있는 줄을 고르고 유형을 붙임).
5. **오늘의 카드(모바일):** 진행 링, 연속 일수, 복습 대기·새 카드·익힌 카드 수를 본 뒤 시작한다. 빈칸은 처음부터 정답 글자 수만큼 보이고(길이 힌트), 그보다 길게 쓰면 가로로 늘어난다. 풀고 나면 해설 아래에 함수 문법이 방언별로 붙는다(카드 방언이 먼저).
6. **공고 분석:** 공고 본문을 붙여넣으면 요구 역량 칩(예: 퍼널 분석, 코호트와 리텐션)과 추천 문제 목록이 나온다. 본문은 브라우저에만 저장되고 AI 호출이 없다.
7. **AI가 쓴 쿼리 검증(쿼리 리뷰):** 분석 도우미가 써 준 것처럼 그럴듯한 쿼리가 줄 번호와 함께 나온다. 줄을 누르면 결함 유형 칩이 펼쳐지고, 고르면 줄에 유형 배지가 붙는다. 채점하면 줄마다 맞음·유형 다름·결함 아님이 표시되고 "결함 3개 중 2개 찾음 · 결함 아님 1줄" 같은 배너가 뜬다. 통과하거나 정답을 열면 놓친 결함 줄, 결함별 설명, 맞는 줄(함정) 설명, 올바른 결과·쿼리가 나온다. 같은 쿼리도 방언을 바꾸면 결함 수가 달라진다(정수 나눗셈은 PostgreSQL에서만 결함).
8. **모의 시험:** 제한 시간 타이머, 문제 이동, 종료 후 문제별 시도 횟수와 정답까지 걸린 시간을 요약한다. 시험 중에는 해설과 기대 결과를 숨긴다.

## 4. 사용자 퍼널

화면 이동 기준의 흐름이다. 이 서비스는 사용 이벤트를 수집하지 않으므로 단계별 전환 수치는 없다. 진행 기록은 사용자 브라우저(localStorage)에만 남는다.

### 유입

- 홈(`/`)에서 분류별 세트 카드로 들어간다.
- 채용 공고로 들어간다(`/jd`): 공고 붙여넣기, 요구 역량, 추천 문제, 문제 풀이 순이다.
- 매일 알림으로 들어간다(`/daily`): 알림을 누르면 오늘의 카드가 열린다.
- 홈 화면에 설치한 앱(PWA)에서 바로 오늘의 카드로 들어간다.

### 문제 풀이 흐름

1. 홈에서 세트를 고른다(기초 문법, 직무별 실무, KPI 대시보드).
2. 세트 화면(`/sets/<id>`)에서 문제 목록을 보고, 이미 통과한 문제를 확인한 뒤 문제를 연다.
3. 문제 화면(`/problems/<id>`)에서 요구 조건과 스키마를 읽고 방언을 고른다.
4. 쿼리를 쓰고 실행한다(Cmd/Ctrl+Enter).
5. 오답이면 원인 라벨과 누락 행을 보고 고쳐 다시 실행한다. 힌트는 단계별로 연다.
6. 정답이면 해설, 방언별 정답 쿼리, 자주 나오는 오답이 열린다.
7. 세트 목록으로 돌아가면 "통과" 표시가 남아 있다. 방언, 마지막 쿼리, 통과 여부는 새로고침해도 유지된다.

### 오늘의 카드 흐름

1. 시작 화면에서 덱(집계, NULL, 문자열, 날짜, 윈도우 등 10개), 하루 목표(장 수), 방언을 고른다.
2. "시작하기"를 누르면 카드가 나온다. 빈칸에 함수 이름이나 인자를 적는다.
3. "확인"을 누르면 정답/오답, 설명, 실행 결과 표, 함수 문법이 나온다. 막히면 "힌트"나 "모르겠어요"를 누른다. 틀린 카드는 같은 학습 안에서 5분 뒤 다시 나온다.
4. 목표를 채우면 이번 학습 요약이 나오고 "n장 더 풀기"를 할 수 있다. 맞힌 카드는 1·3·7·14·30일 간격으로 다시 나온다.
5. 알림을 켜 두면 다음 날 오전 9시 무렵 알림이 온다.

### 비공개 복습 아카이브

- 개인 복습용 세트 3개(29문제)는 비밀번호로 잠겨 있다. 홈에는 자물쇠 아이콘이 붙은 카드로 보이고, 들어가면 비밀번호 입력 화면만 나온다.
- 모의 시험 세트는 현재 이 아카이브에만 있다.
- 포트폴리오에는 이 세트의 문제 화면, 문제 제목, 출처를 싣지 않는다. 잠금 화면과 홈의 자물쇠 카드까지만 쓴다.

### 화면 구성

- **공통:**
  - 어두운 배경을 쓴다. 강조색은 파랑, 정답은 초록, 오답은 빨강이다.
  - 상단 내비는 오늘의 카드, 문제 세트, 모의 시험, 공고 분석이다.
  - 코드와 결과 표는 고정폭 글꼴이다.
- **홈:**
  - 히어로에 "데이터 분석가 라이브 쿼리 연습"과 "오늘의 카드", "채용 공고로 문제 고르기" 버튼이 있다.
  - 아래로 분류별 세트 카드가 이어진다(기초 문법 10, 직무별 실무 7, KPI 대시보드 2, 비공개 복습 아카이브 3).
  - 카드에는 연습/모의 시험 배지와 문제 수가 붙는다.
- **문제 풀이(데스크톱 3단):**
  - 왼쪽: 출처·난이도 배지, 권장 시간, 제목, 상황 설명, 요구 조건, 개념 태그, 힌트.
  - 가운데: 방언 선택(PostgreSQL, BigQuery, MySQL)과 엔진 상태(준비됨), 실행 버튼, SQL 편집기(테이블·컬럼 자동완성), 채점 배너, 결과 탭(내 결과, 기대 결과, 누락 행).
  - 오른쪽: 데이터셋 설명과 함정, 지표 정의, 테이블 목록(펼치면 컬럼과 샘플 5행).
  - 모바일에서는 문제, 쿼리, 스키마 탭으로 나뉜다.
- **오늘의 카드:**
  - 상단에 진행 바(0/10)가 있다.
  - 카드는 덱 이름, 방언(공통이면 "공통"), 응용 표시, 새 카드/복습 배지, 한 줄 설명, 빈칸이 들어간 SQL로 이뤄진다.
  - 아래에 힌트, 모르겠어요, 확인 버튼이 있다.
  - 채점 뒤에는 정답/오답, 설명, 실행 결과 표가 나온다. 오답이면 입력한 값에 취소선이 그어지고, "다음 문제"로 넘어간다.
  - 그 아래 "문법" 칸에 함수 이름, 한두 문장 설명, 방언별 형태(공통, PostgreSQL, BigQuery, MySQL)와 주의점이 나온다.
- **공고 분석:**
  - 공고 입력란과 분석 버튼이 있고, 옆에 "역량 n개, 추천 n문제"가 붙는다.
  - 요구 역량은 칩으로 보이고, 공고에서 찾은 키워드가 함께 표시된다.
  - 추천 문제는 출처, 형식, 역량 태그, 난이도와 함께 번호 목록으로 나온다.

### 캡처 방법

- 운영 사이트가 공개라 로그인 없이 바로 캡처할 수 있다. 데모 데이터만 있고 실사용자 데이터는 없다.
- 오답 장면은 문제 화면에서 출력 컬럼이 다른 쿼리(예: `SELECT * FROM orders`)를 실행하면 "출력 컬럼 확인" 라벨이 뜬다. 원인 라벨이 더 구체적인 장면은 해당 문제의 "자주 나오는 오답" 쿼리를 실행해서 만든다.
- 문제 원문은 저장소에 없다. 로컬에서 원문을 읽는 캡처 스크립트는 `e2e/screenshots.mjs`다(로컬 `content/`, `.env.local` 필요).
- 운영 사이트는 MySQL이 연결돼 있지 않아 MySQL을 고르면 미연결 안내가 뜬다. 세 방언 장면은 PostgreSQL, BigQuery로 찍거나 로컬 MySQL로 찍는다(README "개발").

## 7. 구현

셀링 흐름 뒤에 붙는 기술 챕터용 자료다.

### 실행 엔진

- PostgreSQL은 PGlite(브라우저 WASM)로 사용자 브라우저 안에서 실행한다. 서버 비용이 들지 않는다.
- BigQuery는 DuckDB-WASM 위에 BigQuery 방언 변환층(`lib/engine/bq-shim.ts`)을 얹어 실행한다. 백틱 식별자, `DATE_TRUNC`·`DATE_DIFF` 인자 순서, `SAFE_CAST`, `COUNTIF`의 NULL 처리 등을 바꿔 준다.
- MySQL은 서버 Route Handler가 원격 MySQL에서 실행한다. 조회 쿼리만 허용하는 읽기 전용 가드가 있다.
- 데이터셋 시드는 방언 중립 JSON 하나로 두고, 방언별 DDL을 만들어 세 엔진에 같은 데이터를 넣는다.

### 채점과 오답 진단

- 채점은 정답 결과 집합과 사용자 결과를 비교한다. 정렬이 요구된 문제만 순서를 보고, 숫자 허용 오차와 NULL을 정규화한다.
- 진단은 두 단계로 한다.
  1. 문제마다 미리 실행해 둔 오답 패턴의 결과 해시와 사용자 결과 해시를 대조한다. 일치하면 해당 오답 라벨과 설명을 낸다.
  2. 일치하는 패턴이 없으면 규칙으로 원인 후보를 낸다. 규칙은 컬럼 수, NULL, 정수 나눗셈, 정렬, 행 수가 기대의 정수배(조인 팬아웃), 행 수 과부족, 값 불일치다.
- 오답 진단 평가는 12/12, 목표는 80%다(`scripts/eval-diagnose.ts`).
- 쿼리 리뷰는 줄 단위 체크리스트로 채점한다. 결함마다 결함 줄 목록과 유형이 있고, 사용자의 (줄, 유형) 표시를 맞음·유형 다름·결함 아님으로 판정한다. 모든 결함을 찾고 오탐이 없어야 통과다.
- 결함 줄은 줄 번호가 아니라 문자열로 지정하고 빌드가 방언별 줄 번호로 푼다. 양식 통일로 줄이 다시 나뉘어도 깨지지 않는다. 같은 방언 안에서 결함 줄이 겹치거나, 결함이 결과를 바꾸지 않으면 빌드가 실패한다.
- 검토 쿼리의 결과는 방언별로 미리 실행해 둔다. 같은 코드가 PostgreSQL에서는 정수 나눗셈, BigQuery·MySQL에서는 소수 나눗셈이 되는 것처럼 방언마다 결함과 결과가 다르기 때문이다.

### 콘텐츠 파이프라인

- 문제, 세트, 데이터셋, 카드는 운영 DB(Neon Postgres)에 있고 저장소에는 없다. 앱은 캐시해서 읽고, 게시하면 재배포 없이 반영된다.
- 게시 전 검증은 다음과 같다.
  - 세 방언의 정답 결과가 서로 같은지
  - 오답 패턴이 정답과 다른 결과를 내는지
  - 카드 빈칸에 정답을 넣으면 실행되는지
  - 화면에 보이는 예시 SQL의 줄바꿈·대소문자 양식이 맞는지
- 순서: 시드 생성, 기대 결과 생성(`build-expected`), 카드 검증(`build-cards`), 양식 통일(`format-sql`), 게시(`publish-content`), 캐시 무효화.

### 오늘의 카드와 알림

- 복습 간격은 Leitner 상자 방식이다. 오답은 5분 뒤, 정답은 1·3·7·14·30일 뒤 다시 나온다. 기록은 브라우저 localStorage에 둔다.
- 카드마다 자주 씀/응용 단계를 두고, 새 카드는 날짜 시드로 섞은 뒤 4장 중 1장만 응용 카드로 채운다. 복습할 카드가 먼저 나온다.
- 문법 항목 48개를 카드와 분리해 두고 카드가 id로 참조한다. 같은 함수를 쓰는 카드가 같은 설명을 공유한다.
- 정답 판정은 대소문자 구분 여부를 카드마다 정하고, 템플릿이 따옴표를 감싼 빈칸이면 입력한 따옴표를 무시한다.
- PWA(manifest, 서비스 워커)로 홈 화면에 설치할 수 있다.
- 알림은 Web Push(VAPID)다. 구독은 Upstash Redis에 저장하고, Vercel Cron이 매일 00:00 UTC(한국 오전 9시)에 보낸다. iOS는 홈 화면에 추가한 앱에서만 받는다.

- 잠긴 데이터셋은 MySQL 실행도 막고, 공고 분석 추천에서도 뺀다.
